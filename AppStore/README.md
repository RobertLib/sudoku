# App Store metadata

The App Store Connect texts, kept in the project. Nothing is uploaded
automatically — open the file, copy the contents, paste it into the matching
field in App Store Connect.

The folders are named after the fastlane convention (`cs`, `en-US`), so
if you ever decide to move to `fastlane deliver`, renaming `AppStore/` to
`fastlane/metadata/` is all it takes.

## Where everything goes

App Store Connect → **Apps → Sudoku → iOS App → 1.0 Prepare for Submission**
(the version in `MARKETING_VERSION` — keep the two in step). There is a language
switch at the top — every field is filled in separately for each language.

| Field in App Store Connect | File | Limit | Currently |
|---|---|---|---|
| App Name | `<language>/name.txt` | 30 characters | 26 / 29 |
| Subtitle | `<language>/subtitle.txt` | 30 characters | 29 / 30 |
| Promotional Text | `<language>/promotional_text.txt` | 170 characters | 163 / 161 |
| Description | `<language>/description.txt` | 4000 characters | 3309 / 3313 |
| Keywords | `<language>/keywords.txt` | 100 **bytes** (UTF-8) | 100 / 100 |
| What's New in This Version | — | 4000 characters | not on a first version |
| App Preview and Screenshots | generated by the scripts, see [screenshots.md](screenshots.md) | 1–10 images, up to 3 previews | 10 + video |

(The two numbers are `cs` / `en-US`, in that order.)

The keyword field is the one limit Apple counts in bytes rather than
characters, and a Czech letter with a diacritic is two of them: *číselné* is
7 characters and 10 bytes. The Czech set is 92 characters long and full.

There is no `release_notes.txt` yet, on purpose: App Store Connect has no
*What's New* field on an app's first version. From 1.0.1 on, add one per
language describing what changed since the previous version — replace it for
every release rather than appending to it.

Alternative names, subtitles and keyword sets, the reasoning behind the ones in
use, and what the competition looks like are in
[alternatives.md](alternatives.md).

Checking it. The limits are the easy half — the three checks after them are the
ones that catch real mistakes: a word paid for twice across two indexed fields, a
stray space in the keyword list, and a paragraph left wrapped at 80 columns.

```bash
python3 - <<'PY'
import os,re
lim={'name.txt':30,'subtitle.txt':30,'keywords.txt':100,
     'promotional_text.txt':170,'description.txt':4000}
bad=0
for loc in ('cs','en-US'):
    d=lambda f:open(os.path.join('AppStore',loc,f),encoding='utf-8').read().rstrip('\n')
    for f,m in lim.items():
        # keywords are limited in UTF-8 bytes - every č, á or ř costs two
        n=len(d(f).encode()) if f=='keywords.txt' else len(d(f)); bad+=n>m
        print(f'{loc:6}{f:22}{n:5}/{m}', 'OK' if n<=m else 'OVER!')
    # a word in two indexed fields is paid for twice and indexed once
    t=lambda f:set(re.findall(r'[\wÀ-ſ]+', d(f).lower()))
    for a,b in (('name.txt','subtitle.txt'),('name.txt','keywords.txt'),
                ('subtitle.txt','keywords.txt')):
        ov=t(a)&t(b); bad+=bool(ov)
        if ov: print(f'{loc:6}DUPLICATED {a} x {b}: {sorted(ov)}')
    # a space after a comma silently costs one of the 100 characters
    if ', ' in d('keywords.txt'): bad+=1; print(f'{loc:6}KEYWORDS: space after comma')
    # App Store Connect keeps newlines - a paragraph has to be a single line
    L=d('description.txt').split('\n')
    for i,l in enumerate(L[:-1]):
        if (l.strip() and L[i+1].strip() and not l.isupper() and not l.startswith(chr(8226))
                and not L[i+1].startswith(chr(8226))
                and not l.rstrip().endswith(('.','!','?',':','…'))):
            bad+=1; print(f'{loc:6}DESCRIPTION line {i+1} wrapped mid-paragraph')
print('ALL CLEAN' if not bad else f'{bad} problem(s)')
PY
```

Run it from the repository root, not from this directory. Once a
`release_notes.txt` exists, add `'release_notes.txt':4000` to `lim`.

## Which localisations to create, and why two

Keywords never combine across languages — each localisation is its own search
index — but a storefront supports more than one language. Apple's
[App Store localizations](https://developer.apple.com/help/app-store-connect/reference/app-information/app-store-localizations)
table gives every country a default language and, for most, additional
supported ones, and which of them a customer sees depends on their device
language. The usual ASO reading — Apple's page does not say it in so many words
— is that a storefront searches the keywords of every localisation it supports,
so a second language is extra keyword space in the same country rather than a
different market. The rows that matter here (as listed on 31 October 2026):

| Storefront | Default language | Additional supported languages | What that means here |
|---|---|---|---|
| United States | English (U.S.) | Arabic, Chinese (Simplified), Chinese (Traditional), French, Korean, Portuguese (Brazil), Russian, Spanish (Mexico), Vietnamese | `en-US` is the listing; each of the nine others would be extra US keyword space |
| Czechia | English (U.K.) | **Czech** | `cs` for Czech devices; the rest see the primary language, `en-US` |
| United Kingdom, Ireland | English (U.K.) | — | no English (U.K.) localisation, so the primary language, `en-US` |
| Australia, New Zealand | English (Australia) | English (U.K.) | neither is localised, so the primary language, `en-US` |

So the two folders here are:

- **`en-US`** — primary language of the record, and what every English
  storefront reads.
- **`cs`** — Czechia's additional language, so what every Czech-language device
  there sees, and the one worth the most effort per hour: the
  whole Czech sudoku market is a handful of apps, and the largest one that is
  actually translated into Czech has about 4 300 ratings (see
  [alternatives.md](alternatives.md)).

There is no `en-GB`. It was dropped in November 2026: the UK, Ireland, Australia,
New Zealand and the non-Czech devices in Czechia read the primary language,
`en-US`, instead, US spelling and all. That costs Czechia its second keyword
set.

`es-MX`, `de` and the other big sudoku languages are *not* included: the app's
interface is English and Czech only, so a Spanish- or German-speaking visitor
would arrive at an English app. That is allowed, and plenty of apps do it, but it
trades conversion for reach. Worth trying once there is enough traffic to measure
the trade rather than guess at it — and a German interface would be the
strongest next step of all, because sudoku is unusually big in Germany.

## Notes on the individual fields

- **App Name** — has to be globally unique, and it is the single strongest
  ranking signal. Plain "Sudoku" is taken many times over, and the bare word is
  unwinnable anyway (see [alternatives.md](alternatives.md)), hence
  `Sudoku Offline: Hints, No Ads`: it carries *sudoku*, *offline*, *hints*, *no*
  and *ads* — the two modifiers Apple's own search suggestions rank highest for
  sudoku, plus the app's differentiator — while still reading like a title. On
  the home screen the app stays just "Sudoku" (`INFOPLIST_KEY_CFBundleDisplayName`),
  which Apple does not mind — the home screen name only must not differ in
  *meaning*, and a store name that starts with the same word does not.
- **Subtitle** — the second strongest signal and the line people actually read in
  search results. It adds the terms the name could not fit (*daily*, *puzzle*,
  *learn*, *techniques*) rather than repeating it. **No price in it**, in any
  language, and none in the keywords either: guideline 2.3.7 covers every
  metadata field alike, and *zdarma* / *free* is the wording that gets metadata
  rejected. "No ads" /
  "bez reklam" is not a price and is fine — Apple accepts it in names that have
  been live for years (*Sudoku ′ No ads*, *Sudoku No Pop-up Ads*).
- **Keywords** — separate with commas and **no spaces** (a space counts towards
  the limit). Do not repeat words already in the name or subtitle, Apple indexes
  those separately; that is why *sudoku*, *offline*, *hints*, *no*, *ads*,
  *daily*, *puzzle*, *learn* and *techniques* are missing from the English lists.
  Do not name a competitor's app or brand — *sudoku.com*, *brainium*, *easybrain*,
  *good sudoku* and *nyt* are all somebody else's, and grounds for rejection.
- **Description** — write each paragraph as **one long line**. App Store Connect
  keeps newlines exactly as pasted, so a paragraph wrapped at 80 columns in the
  editor comes out ragged on the device while every other paragraph reflows
  around it. Note also that on iOS the description is **not indexed for search**
  — it is a conversion field only, so keywords in it buy nothing and the first
  three lines (all most people ever see) are what the effort belongs in.
- **Promotional Text** — the only text on the product page that can be changed
  at any time, "without requiring an updated submission" in Apple's words: no new
  version, no new build. Useful for seasonal or topical messages. Like the
  description, it is not indexed for search.

## Settings that are not filled in with text

**App Information** (shared across all languages):

- Primary Category: **Games**, subcategories **Puzzle** and **Board** — where
  every large sudoku app sits (Sudoku.com, Brainium, PeopleFun and Oakever all
  list Board + Puzzle).
- Secondary Category: **Education**. The hints are the app's reason to exist —
  24 techniques, each explained on the board — and Education is a far smaller
  room than Entertainment, where most of the competition puts its secondary
  category and where an app without six-figure ratings never shows. *Sudoku by
  Staple Games* (104 000 ratings) does the same. If Apple's reviewer disagrees,
  Entertainment is the conventional fallback; nothing else depends on it.
- Content Rights: **does not contain third-party content.** The puzzles are
  generated by the app, and the hints, the guide, the icon and the synthesized
  sounds are the project's own.
- **Gambling: No.** No real money, no wagering, nothing to buy.

`INFOPLIST_KEY_LSApplicationCategoryType = public.app-category.puzzle-games` is
already set on the app target, so the bundle says the same thing about itself
that the listing does. (It has no effect on the iOS App Store — it is the Mac
App Store key — but it costs nothing to keep in step.)

**Age Rating: 4+.** Apple's questionnaire was rebuilt in 2025 (tiers 4+, 9+,
13+, 16+, 18+, with new sections for in-app controls, capabilities and
medical or wellness topics, and a social media question added in 2026). Every
answer here is *None* or *No*:

- In-App Controls: Parental Controls **No**, Age Assurance **No**.
- Capabilities: Unrestricted Web Access, User-Generated Content, Social Media,
  Messaging and Chat — all **No**. **Advertising — No**, which is the answer most
  of this category cannot give: the sudoku apps carrying 9+ and 13+ are almost
  all carrying it for their ad networks.
- Mature Themes, Sexuality or Nudity, Violence — all **None**.
- Medical or Wellness: **No** to both. Do not answer *Health or Wellness Topics*
  with Yes on the strength of "sudoku is good for your brain" — it moves the
  rating to 9+, and the listing deliberately makes no such claim.
- Chance-Based Activities: Gambling, Simulated Gambling, Contests, Loot Boxes —
  all **None**. Sudoku is pure logic, and the achievements are earned, not drawn.

**Pricing and Availability:** Free, in every country and region **except China
mainland** — in *Pricing and Availability → App Availability*, choose *Specific
Countries or Regions* (or later *Manage → Manage Availability*) and deselect
it. Apple's
[App information](https://developer.apple.com/help/app-store-connect/reference/app-information/app-information)
reference says games there "must secure an approval number" from China's
National Press and Publication Administration (NPPA), and that MIIT requires
some apps to have an ICP Filing Number; this project has neither. Left
selected, China mainland does not block the submission — App Store Connect just
reports the app as unavailable there (*Missing Game registration number*,
*ICP Filing Number Missing*) — but deselecting it says so up front instead of
leaving a standing warning. Should a Chinese release ever be wanted, both go
under *App Information* with their supporting documents.

**App Privacy:** click *Get Started* → **"No, we do not collect data from this
app"**. The app has no networking code, no third-party SDKs, and stores
everything on the device: the settings in UserDefaults (declared in
`sudoku/PrivacyInfo.xcprivacy`, reason CA92.1), games, statistics, daily results
and achievements as JSON files in Application Support and pre-generated puzzles
in Caches, which need no declaration. No other required-reason API is used —
the timer measures with `Date`, not with the system uptime. A **privacy policy
URL is still mandatory** — the text is ready in [privacy-policy/](privacy-policy/);
the simplest home is the repository itself, which is public:
`https://github.com/RobertLib/sudoku/blob/main/AppStore/privacy-policy/en.md`
(push first). GitHub Pages or your own site work just as well.

**Accessibility Nutrition Labels** (App Store Connect → the app → *App
Accessibility*): voluntary today, and shown on the product page from iOS 26 on.
Declare only what has been checked, for iPhone and iPad:

- **VoiceOver: Yes.** Every cell says its position, its number or notes and
  whether it is wrong; every control is labelled; a whole game can be played.
- **Dark Interface: Yes.** Light, dark and system appearance, every screen.
- **Reduced Motion: Yes.** With the system setting on, a wave across the board
  becomes one gentle pulse, and the shake on a wrong number and the confetti
  are left out.
- **Larger Text: No.** Text grows with Dynamic Type everywhere except around the
  board, where it stops at the first accessibility size on purpose, because the
  board itself cannot grow. Apple's criterion is the common tasks at 200 %, and
  playing a game is the common task.
- **Differentiate Without Color Alone:** a wrong or repeated number is red and
  sits in a tinted cell; with the system setting on it is underlined as well, and
  VoiceOver says it too. Declare it once checked on a device.
- **Sufficient Contrast, Voice Control:** leave unanswered until checked.
- **Captions, Audio Descriptions:** not applicable — the app has no video or
  spoken content.

**Support URL:** a mandatory field. The repository page
(`https://github.com/RobertLib/sudoku`) or a simple page with an e-mail address
will do.

**Marketing URL:** optional, feel free to leave it empty.

**Encryption:** `INFOPLIST_KEY_ITSAppUsesNonExemptEncryption = NO` is already set
in the project, so the export compliance question never appears when the build is
uploaded.

**App Review Information** → the note for the reviewer is in
[review-notes.txt](review-notes.txt). The game needs neither an account nor a
demo login — leave *Sign-in required* switched off.

**In-App Events** (App Store Connect → the app → *Events*): not needed to ship,
but the largest piece of indexed text left once the listing is live. The event
**name (30)** and **short description (50)** are both indexed for search, in
every localisation. This app has a natural event to hang
them on: a monthly *Challenge* event — "Thirty days of sudoku" in November,
solve every daily challenge of the month — which the app already counts with
its calendar, its streak and the *Monthly Habit* achievement (complete 30 daily
challenges). A new one each month keeps a fresh indexed name live all year.
Worth setting up after launch.

## Release procedure

1. Xcode → Signing & Capabilities, check the team `K6GM85X5D7` and the bundle ID
   `cz.rob.sudoku`.
2. App Store Connect → **Apps → +** → new record, bundle ID `cz.rob.sudoku`,
   primary language **English (U.S.)** — the fallback for every storefront
   without its own localisation — SKU e.g. `sudoku-001`, name from
   `en-US/name.txt`. Names are globally unique; if it has been taken by the
   time you get there, see the alternatives in
   [alternatives.md](alternatives.md).
3. Add the other localisation: App Information → the language switch, top
   right → **Czech**.
4. Fill in the texts from this directory in every language.
5. Build the media with `Tools/appstore_media.sh` and then
   `Tools/appstore_compose.sh`, and upload the **composed** screenshots and the
   previews — see [screenshots.md](screenshots.md). Every slot has a folder and
   a preview file of its own, named after it: **iPhone 6.1"/6.3"** (`iphone-6.3`),
   the one iPhone slot Connect requires; **iPad 13"** (`ipad-13`), required too,
   because the app is universal; and **iPhone Duo** (`iphone-duo`), required
   from April 2027, with which the product page gets the *Made for iPhone Duo*
   badge.
6. Check `MARKETING_VERSION` (1.0) and **`CURRENT_PROJECT_VERSION`** (the build
   number, `CFBundleVersion`) in the project. Raise the build number on every
   upload, rejected ones included: Connect only requires it to be unique within
   a version string, but every tool that reads build numbers assumes they only
   ever go up.
7. Xcode → Product → Archive → Distribute App → App Store Connect → Upload.
8. Wait for the build to process (10–60 min), then select it in the *Build*
   section.
9. Fill in App Privacy, Age Rating, Pricing and Availability (China mainland
   deselected, see above) and the Accessibility Nutrition Labels.
10. **Add for Review** → *Submit*.

From 1.0.1 on it is **+ Version or Platform** instead of a new record; the
localisations are inherited, `release_notes.txt` is the one field that has to
change for every version, and the rest only needs touching when it is actually
out of date. Of the listing's texts and media, only Promotional Text changes at
any time. Screenshots and previews belong to a version: Apple takes them for review only
while one is being prepared (*Prepare for Submission*, or after a rejection),
so new media go up with the next version. The one way around that is
[Product Page Optimization](https://developer.apple.com/help/app-store-connect/create-product-page-optimization-tests/apply-a-test-treatment-to-your-product-page):
test the new set as a treatment on the live app, then apply it to the original
product page, which Apple allows at any time — for screenshots and previews
only; an icon still needs a new version.
